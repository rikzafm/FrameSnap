# 08 — Offscreen document: ffmpeg engine, chunk store, fetch-loop host

Status: resolved
Blocked by: 03
Spec: ../spec.md §4, §6.3, §6.6

## What
- Offscreen doc lifecycle: created on demand (reasons `BLOBS`, `WORKERS`), closed after 60 s idle with no job.
- Engine: bundled single-thread `@ffmpeg/core`. `run(args[], onProgress, signal)`, where cancel = `terminate()` + reload. Write inputs from `assembleTrack()` blobs, read the output as a Blob, and return a `blob:` URL (revoked after save).
- Host `runFetchPhase` with `OpfsChunkStore` and `fetch`. Forward `onCommit`/`onProgress` to the SW over the `engine` port. Fall back to `MemoryChunkStore` on an OPFS/quota error, and report `resumable: false`.
- `navigator.storage.persist()` once; report `navigator.storage.estimate()` to the SW for `storeCap`.
- GIF: run `buildGifArgs` pass 1 then pass 2.

## Done when
- Engine suite (`npm run test:engine`, Node + `@ffmpeg/ffmpeg`, generated 2 s clips): remux, DASH pair mux, HLS TS → MP4 copy, trim, MP3, GIF.
- Browser test: an OPFS store write → list → read → deleteJob round trip; a write interrupted before close() leaves no file.
- Cancelling mid-encode frees the engine, and the next job runs.

## Answer

The offscreen engine, fetch-loop host and OPFS store are built and covered by three suites.

- `src/offscreen/engine.ts`: `Engine` over an `FfmpegBackend` (`backend.ts`). `run(args, onProgress, signal)` runs one command line; `encode({inputs, commands, output, mime, scratch}, onProgress, signal)` writes the input blobs, runs the commands in order (GIF = palette pass, then render pass), reads the output as a Blob and clears the engine FS. Jobs are queued, one at a time. Aborting the signal calls `terminate()`; the next job reloads a fresh runtime. Abort gives `cancelled`; an out-of-memory failure gives `oom`.
- `src/offscreen/ffmpeg-backend.ts`: the browser backend (`@ffmpeg/ffmpeg` with the bundled single-thread `@ffmpeg/core` and wasm, via Vite `?url`).
- `src/offscreen/host.ts`: `createEngineHost(deps)` takes commands from the SW, runs `runFetchPhase`, forwards `onCommit`/`onProgress`, runs the download and GIF encodes (`buildDownloadArgs`/`buildGifArgs`), returns a `blob:` URL, and frees it on `engine/revoke`. It falls back to a shared `MemoryChunkStore` on an OPFS or quota error (any non-abort `DOMException`, or `quota`) and reports `engine/fetched {resumable: false}`. It calls `navigator.storage.persist()` once and reports `estimate()` on connect and on `engine/storage`. `src/offscreen/main.ts` wires it to the `engine` port.
- `src/core/engine-messages.ts`: `WorkerToEngine` / `EngineToWorker` messages and guards. Ticket 09 builds the SW side on these.
- `src/background/engine-lifecycle.ts`: `createEngineLifecycle` creates the offscreen document on demand (`BLOBS`, `WORKERS`) and closes it 60 s after the last job finishes. Ticket 09 calls `jobStarted`/`jobFinished` and wires it to the `offscreen` wrapper in `platform/chrome.ts`.
- `src/offscreen/opfs-chunk-store.ts`: a chunk is now written to `<key>.part` and renamed on completion. `getFileHandle({create})` makes an empty file at once, so writing to the final name left a 0-byte chunk after an interrupted write. `list()` ignores `.part` and Chrome's `.crswap` files.

Tests
- `npm run test:engine` (`tests/engine/engine.test.ts`): remux (MP4 to MKV), DASH video + audio mux, HLS TS to MP4 copy, trim, MP3, GIF, cancel mid-encode then a next job. Clips are generated by the engine itself with lavfi, so no ffmpeg binary is needed. `@ffmpeg/ffmpeg` needs a Web Worker, which Node lacks, so the Node suite drives the same `@ffmpeg/core` wasm through a worker_threads `FfmpegBackend` (`tests/helpers/node-backend.ts`, `node-core-worker.mjs`).
- `npm run test:browser` (`tests/browser/`, `vitest.browser.config.ts`): real OPFS in the installed Chrome (write, list, read, deleteJob; an interrupted write leaves no file). Needs Chrome installed; no browser download.
- Unit: `tests/unit/engine-host.test.ts`, `engine-lifecycle.test.ts`, `engine-messages.test.ts`.

`npm test` now runs `tests/unit` only; the engine and browser suites have their own scripts.
